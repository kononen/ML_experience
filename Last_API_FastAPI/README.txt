ЗАПУСК ПРИЛОЖЕНИЯ

1) Активировать виртуальное окружение (из папки API_FastAPI):
   source API_FastAPI/venv_FastAPI/bin/activate

2) Запустить API (из папки API_FastAPI):
   uvicorn app.api:app --reload
   На сервере/в окружении ЗК добавить: --host 0.0.0.0


ВАЖНО ПРО JSON

JSON-клиентам (curl, Postman и т. п.) нужно отправлять «пустые» значения именно как null, а не как NaN!!!


POST-ЗАПРОСЫ

1) Отправка запроса из файла:
curl -X POST "http://localhost:8000/predict"      -H "Content-Type: application/json"      -d @payload.json

2) Пример inline-запроса:
curl -X POST "http://localhost:8000/predict"      -H "Content-Type: application/json"      -d '{
           "clients": [
             { "cat":"A",   "num1": 0.0,    "num2": 10.0,  "num3": null, "num4": 5.0 },
             { "cat":"B",   "num1": -50.5,  "num2": 150.0, "num3": 1.0,  "num4": 100.0 },
             { "cat":null,  "num1": 100.0,  "num2": 0.0,   "num3": 0.0,  "num4": -10.0 },
             { "cat":"C",   "num1": 50.0,   "num2": 200.0, "num3": 1.0,  "num4": 3.14 },
             { "cat":"A",   "num1": -100.0, "num2": 199.9, "num3": null, "num4": 0.0 }
           ]
         }'

• status:

• health:
  curl http://127.0.0.1:8000/health


ВОЗМОЖНЫЕ КОДЫ И ОПИСАНИЯ ОШИБОК (GET /status/{task_id} и GET /results/{task_id})

1) /status:
   • 200 — если всё ок
   • 400 — если пустой список
   • 404 — если хотя бы один task_id не найден
   • 500 — любой другой сбой

2) /results:
   • 200 — даже если некоторые или все task_id не найдены (возвращаем "status":"not_found" в теле)
   • 400 — если пустой список
   • 500 — при сбое БД/кода


ПОВЕДЕНИЕ ПРИ ВЫСОКОЙ НАГРУЗКЕ / КОНКУРЕНТНЫХ ЗАПРОСАХ

Я пробовал делать одновременно POST-запросы с одними и теми же входными данными
(JSON с ~15 тыс. записей и ~149 признаками) одновременно с двух серверов
(4 и 3 запроса параллельно), а также по отдельности: с первого сервера 4 запроса параллельно,
со второго 3 запроса параллельно. Количество ответов 200 OK и 503 Service Unavailable получается разным.


ПОЧЕМУ ВОЗВРАЩАЕТСЯ 503 Service Unavailable

• Если в базе уже есть невыполненная (или «зависшая») задача — возвращаем клиенту HTTP 503,
  потому что новая задача не может быть поставлена, пока предыдущая ещё не завершилась.

• Если при подключении к базе что-то пошло не так (например, не смогли соединиться),
  any_task_processing() тоже возвращает True (логгирует ошибку и «берёт безопасность»),
  чтобы не принимать новые запросы, пока с БД проблемы.


ПРОВЕРКИ БАЗЫ ДАННЫХ ПРИ СТАРТЕ

• Если база данных ml_api_db не создана — connect() упадёт, вы увидите ошибку подключения:
  database "ml_api_db" does not exist

• Если база есть, но в ней нет какой‑либо из таблиц tasks или logs — упадёт уже в проверке to_regclass:
  RuntimeError("Required table '…' does not exist").

Таким образом API гарантированно не начнёт работу, пока не будет уверенности в том,
что и сама БД, и нужные в ней таблицы присутствуют.
